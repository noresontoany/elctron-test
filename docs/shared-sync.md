# Общая синхронизация вкладок

## Что изменилось

На вкладке остаются TanStack DB, реактивные join/aggregate запросы и оптимистичные транзакции. SharedWorker владеет четырьмя **официальными Electric collections**, которые содержат только подтверждённые сервером строки. Он передаёт вкладкам начальный снимок и дальнейшие изменения через MessagePort. HTTP-записи выполняет вкладка через обычный API.

| Сценарий в одном браузерном профиле и origin | Подписки Electric |
| --- | ---: |
| 1 пользователь, 1 вкладка, 4 коллекции | 4 |
| 1 пользователь, 10 вкладок, 4 коллекции | 4 |
| 2 разных пользователя, 10 вкладок всего | 8 |
| 10 пользователей или независимых устройств | 40 |
| 1 пользователь, 20 разных shapes, 10 вкладок | 20, если все вкладки используют те же shapes |

Это экономия **повторяющихся подписок**, а не отсутствие лимитов. Разные origin (`localhost` / `127.0.0.1`, HTTP / HTTPS, разные порты), браузерные профили и устройства не делят worker. Данные каждой вкладки всё ещё занимают память; реактивные запросы и рендер выполняются в каждой вкладке. Большие снимки копируются через structured clone. Кеш Electric на сервере может переиспользовать одинаковые shapes независимо от браузерных workers.

## Файлы для чтения

- [`sync.worker.ts`](../frontend/src/shared/sync/sync.worker.ts) — официальные Electric collections, владельцы подписок, проверка сессий, снимки и изменения.
- [`collection.ts`](../frontend/src/shared/sync/collection.ts) — адаптер TanStack DB в окне, RPC и передача подтверждения записи.
- [`protocol.ts`](../frontend/src/shared/sync/protocol.ts) — типизированный протокол MessagePort.
- [`collection.ts` заказов](../frontend/src/entities/order/model/collection.ts) — REST-мутации и ожидание `awaitTxId`.
- [`session_router.py`](../backend/src/containers/session/routes/session_router.py) — проверенный сервером контекст пользователя.

Зависимости направлены по FSD: `entities → shared/sync`; worker не импортирует доменные сущности. DTO проверяются схемой сущности при применении данных в окне. Nuxt не включает файл, загруженный через `new URL`, в обычный граф TypeScript, поэтому у worker отдельный `tsconfig.worker.json` и обязательная проверка в `make check`.

## Гарантии и ограничения

1. Worker проверяет bearer-токен каждого порта через `GET /api/session`. Ключ разделения — мастерская, ID пользователя, роль и ресурс. Переданный вкладкой ID пользователя не является основанием для доступа. Разные подписанные токены одного пользователя могут разделить коллекцию. Проверка повторяется раз в минуту; 401/403 или смена роли отключают порт. Сетевой сбой повторной проверки не уничтожает подписки. Права записи API проверяет при каждом запросе.
2. Новая вкладка получает снимок уже материализованной коллекции после `preload`, затем изменения. Смена Electric handle, `must-refetch`, повторы и доказательства транзакций обрабатывает официальный адаптер. Собственного парсера Electric в браузере нет.
3. Вкладка отправляет `awaitTxId(txid)` worker-у. Worker ждёт официальный `collection.utils.awaitTxId`. Изменения идут в тот же FIFO MessagePort **перед** ответом RPC. Вкладка принимает sync commit, а затем завершает оптимистичную транзакцию. Нельзя ожидать receipt commit перед обработкой RPC: при оптимистичной записи это создало бы взаимную блокировку.
4. `pagehide` снимает подписку; закрытие последнего порта очищает исходную коллекцию и отменяет запрос. Heartbeat удаляет зависшие порты через 120 секунд. После восстановления из BFCache страница перезагружается. Замороженная дольше lease вкладка требует обновления.
5. У порта ограничена очередь неподтверждённых пакетов: 256. Вкладка подтверждает приём каждого пакета. Если она не справляется, её подписка закрывается с ошибкой вместо неограниченного накопления сообщений. Это не ограничение размера одного снимка.
6. При отсутствии SharedWorker используется отдельный worker вкладки. `?sync=direct` принудительно включает этот режим для сравнения. И там, и там источник — один и тот же официальный адаптер. Это не переключатель на REST polling.
7. Четыре коллекции пока загружаются целиком (`eager`) для мастерской. Между разными shapes нет обещания единого атомарного снимка всех таблиц. Для больших объёмов следующий эксперимент — ограниченные shapes / on-demand, включая корректные фильтры на сервере; менять их только в UI недостаточно.

В DevTools можно выполнить `await window.spokeSync()`: режим, число подписчиков, размер коллекций, число запросов и активных запросов. Токены в диагностике отсутствуют. Консольная функция предназначена для этого учебного стенда.

## HTTP/2 и отмена запросов

SharedWorker не заменяет HTTP/2: два пользователя могут держать восемь долгих запросов. Локально HTTPS работает на **https://localhost:8447**, старый HTTP — на 8097. Caddy соседних проектов не затрагивается. Для браузера нужно доверие к локальному сертификату, см. [инструкцию стенда](load-testing.md).

Убрано `flush_interval -1`: в Caddy оно отключает отмену upstream-запроса при отключении клиента. Для buffered long polling это оставляло лишние запросы до таймаута. Proxy теперь также отменяет httpx-запрос при отключении клиента и освобождает свой слот в `finally`. Проверка Origin и метрики реализованы чистым ASGI middleware: вариант на `BaseHTTPMiddleware` скрывал `http.disconnect` от обработчика. Это проверяется отдельным интеграционным тестом через настоящий Caddy, а не только подставным Request.
